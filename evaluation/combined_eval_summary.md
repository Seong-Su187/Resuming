## 레이어별 요약

### 음성 (CER 1.3%)
목표(10% 이하)를 크게 상회해서 통과. TTS→STT 왕복 30문장 중 대부분 완전 일치, 일부 조사/띄어쓰기 차이 정도만 있었음. 추가 개선 불필요.

### 영상 (LSE-C 4.68, 목표 6 미달)
MuseTalk 립싱크 정확도가 목표에 못 미침. 원인 조사 결과:
- 시간축 스무딩(떨림 완화용) ON/OFF 비교 → 차이 0.2 미만으로 원인 아님을 확인
- MuseTalk 자체가 Wav2Lip 계열보다 LSE-C가 낮게 나오는 구조적 경향 + 입 영역 해상도가 주 요인으로 추정
- **개선 시도**: SoulX-FlashHead(다른 립싱크 모델) 테스트 진행 중, 아직 포지셔닝 보정 미완료(추후 재시도 예정)

### RAG① — 이력서+GitHub 기반 질문 생성
- **Recall 0.867**: 검색이 필요한 이력서/GitHub 내용을 대체로 잘 찾아옴 (긍정적)
- **Precision 0.500**: 테스트 이력서가 짧아 청크 수가 적어(3~5개) Top-3 검색이 사실상 상당 부분을 가져오는 구조적 한계 때문 - 실제 검색 품질 문제로 보기 어려움
- **Faithfulness 0.723**: 생성된 질문이 검색된 이력서/GitHub 내용에 대체로 근거함 (긍정적)
- **Answer Relevancy 0.246**: 전 항목에서 고르게 낮음 - RAGAS가 원래 "질문→답변" 구조를 전제로 하는데 우리는 "질문 생성" 태스크라 지표 자체가 잘 안 맞는 것으로 판단됨
- **개선 포인트 발견**: "지원 동기" 관련 질문에서 서로 다른 두 이력서 모두 완전히 동일한 질문이 생성됨 - 검색은 각 이력서의 실제 지원 동기 내용을 잘 찾아왔는데, 생성 단계에서 `generate_single_question`의 시스템 프롬프트에 박힌 예시 문구를 그대로 베낀 것으로 확인. 프롬프트에서 예시 질문을 제거하거나 "예시를 그대로 재사용하지 말 것"을 명시하면 개선 가능.
- GitHub 요약 컨텍스트를 추가한 이력서(backend_developer)에서도 검색이 이력서 본문 청크를 GitHub 청크보다 우선하는 경향이 확인됨 — 의도된 동작(이력서 본문이 더 구체적인 근거)이라면 문제 아님.

### RAG② — 성장 피드백 (과거 답변 대비 성장 서사)
면접 종료 후 마이페이지에서, pgvector로 같은 지원자의 과거 답변 중 가장 유사한 것 top-1을 찾아 "이전보다 무엇이 나아졌는지"를 LLM이 서술하는 기능에 대한 평가.
- **검색 정확도 0.833**: 과거 답변 풀에서 실제로 가장 관련 있는 항목을 대체로 잘 찾아옴
- **Faithfulness 0.578**: growth_feedback 서술이 실제 제공된 과거/현재 답변 및 지표(jitter/shimmer/시선 이탈/습관어) 범위를 벗어나 근거 없는 성장 서사를 지어내는 경우가 일부 있음 (0.4~0.75 사이 분포) — RAG①보다 낮은 편이라 프롬프트에서 "제공된 수치/텍스트에 없는 내용은 언급하지 말 것"을 더 명시하면 개선 여지 있음
- (개발 과정에서 RAGAS 라이브러리 자체의 버그(한글 텍스트 유니코드 이스케이프로 인한 LLM 채점 왜곡)를 발견해 패치한 뒤 얻은 수치로, 지표 자체의 신뢰도는 확보된 상태)

## 종합 결론 및 다음 액션

1. **음성**: 목표 달성, 추가 작업 불필요.
2. **영상**: 목표 미달. MuseTalk의 구조적 한계로 보이며, SoulX-FlashHead 대체 실험이 진행 중(포지셔닝 보정 남음).
3. **RAG①(질문 생성)**: 핵심 지표(Recall, Faithfulness)는 양호. `generate_single_question`의 HR 질문 프롬프트에서 예시 문구 재사용 문제를 수정하는 것이 가장 즉시 실행 가능한 개선 포인트.
4. **RAG②(성장 피드백)**: 검색 정확도는 양호하나 Faithfulness가 4개 평가 중 가장 낮음(0.578) — growth_feedback 생성 프롬프트에 "제공된 데이터 범위 내에서만 서술" 제약을 강화하는 게 다음 개선 우선순위.
5. **평가 지표 자체의 한계**: RAG의 Context Precision과 Answer Relevancy는 이 프로젝트(짧은 테스트 이력서, 질문 생성 태스크)에 RAGAS를 그대로 적용하기 어려운 구조적 이유가 있어, 수치를 액면 그대로 "성능이 나쁘다"고 해석하지 않는 것이 맞음. RAG②의 검색 정확도도 RAGAS 표준 지표(Context Precision/Recall) 대신 top-1 태스크 특성에 맞춰 hit rate로 단순화해 계산한 것임.
