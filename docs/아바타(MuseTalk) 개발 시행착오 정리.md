# AI 면접관 아바타 개발 정리 (MuseTalk 기반)

발표자료 작성용 참고 문서. 사용 모델/아키텍처, 겪었던 문제와 해결 과정, 최종 정량 평가 결과를 정리했습니다.

---

## 1. 사용 모델 및 기술 스택

| 구성 요소 | 사용 기술 |
|---|---|
| 립싱크 생성 모델 | **MuseTalk v1.5** (실사 얼굴 기반 립싱크 합성) |
| 오디오 특징 추출 | Whisper (MuseTalk 내부 audio feature extractor, STT 아님) |
| 얼굴 파싱 | MuseTalk FaceParsing 모듈 |
| VAE / UNet | sd-vae, musetalkV15 unet (fp16 추론) |
| GPU 실행 환경 | Google Colab (개발/자원관리용 L4 → 데모 최대 성능 확인용 A100) |
| 서버 | FastAPI (Colab에서 직접 구동, ngrok으로 터널링해 백엔드와 연결) |
| 합성 방식 | ffmpeg 기반 실시간 오버레이 합성 (생성된 얼굴을 고정된 duo 배경 위 지정 좌표에 실시간으로 붙임) |
| 얼굴 crop 좌표 계산 | OpenCV Haar Cascade 얼굴 검출 기반 자동 crop |
| STT (면접 답변 인식) | OpenAI Whisper API (`whisper-1`, 별도 백엔드 호출) |

**답변 STT와 MuseTalk 내부 Whisper는 서로 다른 용도**입니다 — 전자는 지원자 음성을 텍스트로 바꾸는 것이고, 후자는 아바타가 "말할 문장"의 오디오를 립싱크용 특징 벡터로 바꾸는 것입니다.

---

## 2. 아바타 구성 및 UX 설계

- **듀오(2인) 면접관 동시 등장**: 기술 면접관(오른쪽) + 인성 면접관(왼쪽)이 한 화면에 항상 같이 나오고, 발화 중인 쪽만 립싱크 애니메이션이 적용됩니다.
- 상황(질문/만족/불만족 등)에 따라 다른 리액션을 가진 아바타를 사용합니다.
- 사전에 아바타 영상을 캐싱해서 Google Drive에 저장하여 관리합니다.

---

## 3. 시행착오 및 해결 과정

### 3-1. 동시 요청 시 502/503 에러
- **문제**: 여러 요청(질문 + 리액션 등)이 겹쳐서 콜랩 GPU 서버로 들어가면 서버가 죽거나 502/503을 반환.
- **원인**: 단일 GPU 서버가 동시에 여러 추론 요청을 처리하지 못하고 충돌.
- **해결**: 백엔드(`_musetalk_colab_lock`)와 코랩 서버(`_inference_lock`) 양쪽에 락을 걸어 요청을 순차 직렬화. TTS 사전 생성 같은 병렬화 가능한 부분은 락 밖에 둬서 성능 손실 최소화.

### 3-2. 문장 단위 분할 스트리밍 + 끊김 없는 연속 재생
- 면접관이 말할 텍스트(질문/리액션)를 문장 단위로 잘라서, **문장별로 TTS 생성 → MuseTalk 립싱크 생성 → 스트리밍 전송**을 파이프라인으로 처리합니다. 다음 문장의 TTS는 현재 문장 영상이 전송되는 동안 미리 생성해둬서, 문장과 문장 사이 대기 시간을 최소화합니다.
- 이렇게 문장별로 따로 생성된 영상들이 사용자 화면에서는 하나로 이어진 자연스러운 발화처럼 재생됩니다 — 이를 위해 아바타의 재생 프레임 위치가 문장이 바뀌어도 이전 문장이 끝난 지점에서부터 계속 이어지도록 관리합니다.

## 4. 정량 평가 결과 (최종)

| 지표 | 결과 | 목표 | 비고 |
|---|---|---|---|
| LSE-C (립싱크 신뢰도) | 4.52 | ≥ 6.0 | 미달 — MuseTalk 자체가 Wav2Lip 계열보다 낮게 나오는 구조적 경향으로 판단 |
| LSE-D (립싱크 거리) | 8.89 | 낮을수록 좋음 | - |
| TTFB (응답 첫 반응까지) | 0.38초 | ≤ 1.5초 | A100 기준, 목표 대비 크게 여유 |
| FPS (생성 속도) | 89.2 | ≥ 25(자체 기준) | 실시간 스트리밍에 필요한 속도 대비 약 3.5배 |

- 서비스가 실제로 쓰는 12개 아바타(질문용 3종 × 2, 리액션용 3종 × 2) 전부를 대상으로 측정했으며, 특정 아바타만 유독 나쁜 경우는 없이 고르게 3.4~6.2 범위(단일 얼굴 기준) 분포.

## 5. 남은 과제

- **STT 비동기/스트리밍 처리**: 현재 답변 STT는 녹음이 끝난 뒤 전체 오디오를 한 번에 Whisper API로 보내는 배치 방식이라, 60초 답변 기준 최대 7~10초 정도 소요됨. 완전한 스트리밍 전환은 오디오 업로드 파이프라인을 웹소켓 기반으로 새로 짜야 하는 큰 작업이라 이번 범위에서는 보류.

## SoulX-FlashHead 립싱크 모델 실험

**별도 노트북(`soulx_flashhead_duo_avatar_server.ipynb`)으로 완전히 독립된 실험**진행.

### 시도 배경
- **SoulX-FlashHead**는 사진 한 장 + 오디오만으로 고개 움직임까지 포함한 영상 전체를 처음부터 생성하는 end-to-end 모델이라 시도함.

### 모델 선택
- **Lite 모델은 단일 RTX4090에서 96FPS, 동시 3스트림에서도 25FPS+**가 나온다는 공식 수치가 있어, 듀오(2인 동시) 용도에 더 적합하다고 판단해 Lite로 진행.
- 오디오 특징 추출은 MuseTalk의 Whisper 대신 `wav2vec2-base-960h` 사용.

### 구현 현황
- 조건 이미지는 원본 duo 영상에서 OpenCV로 얼굴을 검출해 512x512로 크롭해서 사용(SoulX-FlashHead는 항상 512x512 정사각형 입력만 받음).

### 미해결 이슈 — 포지셔닝 보정
- 512x512 조건 이미지를 SoulX가 내부적으로 한 번 더 확대해서 얼굴을 생성함. 이 **내부 확대 배율을 아직 실측하지 못해서**, 생성된 얼굴의 실제 위치/크기가 저희가 배경에 합성하려는 위치와 정확히 맞지 않는 상태.
- 코드에 `SOULX_FACE_ZOOM_COMPENSATION = 1.0`(= 보정 없음)으로 자리만 만들어두고, 실측 후 역수 배율을 넣어 보정하도록 TODO로 남겨둔 상태 — 아직 미보정.
